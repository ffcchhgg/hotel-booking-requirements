# 代码阅读与接口

## 建议阅读顺序

1. `src/main/resources/db/migration/V1__schema.sql`与V2：先看酒店、用户、房型、库存日历、订单、逐夜记录、资金记录之间的外键和唯一性。
2. `identity/Actor.java`与`SecurityConfig.java`：区分登录身份、角色和所属酒店；管理员不意味着拥有所有业务写权限。
3. `catalog/Pricing.java`：理解住宿区间左闭右开、逐夜查价、整数分、学生价和报价有效期。
4. `core/Idempotency.java`与`Db.java`：理解请求去重、事务以及酒店协调行锁，查清业务代码在哪里提交、哪里会回滚。
5. `booking/BookingService.java`：按建单→接单→取消→修改→超时任务的顺序阅读，特别注意修改的两个独立事务。
6. `reception/ReceptionService.java`：分清未来逐夜预订库存与当前实体房间状态。入住不二次扣房量，退房要先进入待清洁。
7. `management/ManagementService.java`与`IncidentService.java`：比较常规审核与应急即时停售，解释为何两者不能共用简单的“修改余房”按钮。
8. `src/test/java/cn/edu/hotel/BookingIT.java`：先选一个正常路径，再读并发接单、故障注入、18:00边界、修改失败与审核冲突测试。

这些是阅读建议，不代表学生已经完成阅读。实际遇到的疑问、修改和理解应另行如实记录。

## 请求约定

浏览器与服务同源，以服务器会话认证。先GET `/api/auth/csrf`获得令牌和请求头名，所有POST带该令牌。业务写入另带`Idempotency-Key`（8—80位字母数字、下划线或连字符，页面生成UUID）。同一操作重试使用原请求键；改变参数需要新键。浏览器页面只保存临时视图状态，不作为业务数据源。

金额单位均为**整数分**；日期`yyyy-MM-dd`；服务裁决使用北京时间；报价、付款和日志时间返回ISO瞬间。列表最多30条，每页参数`page`从1开始。不存在或越范围订单返回404，不解释目标是否存在；未登录401、禁止权限/CSRF403、输入错误400、过期版本或库存价格冲突409。

## 为什么采用同酒店串行协调

库存写操作涉及多晚、多个订单，还可能触发其他待接单订单退款。单纯先查余房再INSERT会出现并发超卖，因此所有会改变同酒店预订能力的业务先锁`hotel`行，再读当前库存和状态。事务结束才释放。这个实现牺牲同酒店写入并行度，换取可解释的锁顺序；课程数据规模已通过20并发验收。高吞吐生产场景可进一步按房型和日期细化，但需要重新证明锁顺序与跨订单处理的一致性。

修改原单与新单的分离是业务要求。第一笔事务成功取消原单后，即使第二笔事务没有成功，第一笔也不能回滚。`modification`记录用于展示和继续进度，不用异常回滚将原单偷偷恢复。

## 工具与代码规范

Java21、Spring Boot3.5.16、Maven3.9.11、PostgreSQL17.12；Java使用Google Java Format1.24.0格式，Maven Checkstyle检查UTF-8、命名、花括号、单行语句、未使用/通配导入等子集，**未宣称完整执行全部Google规则**。前端使用Prettier3.6.2，浏览器验收Playwright1.62.1，版本锁定在pom、wrapper properties和package-lock。

`FaultProbe`仅为可替换的测试注入点，生产Bean为空操作；应用没有远程故障注入或更改服务器时钟接口。测试使用独立库与Mockito时钟，在第一个住宿夜占用、建单写夜后、退款写入后三处抛异常，检查完整回滚。
