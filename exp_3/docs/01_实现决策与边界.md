# 实现决策与边界

本文记录本次代码采用的规则，供运行与后续报告取材；不是新增甲方访谈，也不将实验一的9项待确认需求改写为已确认。

## 从实验二到实验三

实验二是单浏览器会话原型；实验三改为同源HTML/JavaScript界面、Java 21 / Spring Boot 3.5.16服务、PostgreSQL 17.12数据库。原型源文件保持不变。当前开发版本在 `lab3-implementation` 分支，便于与实验二设计交付版本对照。

采用服务类与显式SQL组织业务：`Pricing`负责价格和逐夜可用性，`BookingService`负责订单状态和退款，`ReceptionService`负责实体房间和入住，`ManagementService`负责审核，`IncidentService`负责应急处置。它们通过`Db`和`TransactionTemplate`使用同一事务和酒店协调行锁。这里没有使用JPA实体或虚构不存在的外部支付网关，类图已按实际代码更新。

## 不自动推定的规则

- 提前退房能否退款、退多少；超期后能否继续留住；在住故障补偿、换房或部分退房。当前可登记事项和处理结论，不修改资金或住宿状态来假装完成。
- 外部真实支付、自动拨打电话、短信核验和公安备案。当前均无外部调用。
- 多房型合单、整组付款与整组退款。当前拆单后分别处理，并无整组事务承诺。
- 酒店/房型新增、员工授权后台、实体房间扩建与历史设施版本台账。演示范围先预置3酒店、9房型、48实体房间及所属前台；维护展示资料、日历价格与可售量，不允许删除历史引用对象。

## 安全与一致性实现

会话认证由Spring Security完成，登录后更换会话ID，Cookie设置HttpOnly和SameSite=Lax，所有写接口校验CSRF。顾客注册不接受角色或酒店字段。顾客只能查询本人订单，前台只能操作所属酒店，管理员查询范围广但没有前台或代客取消写权限。

关键写操作先保存请求键与载荷摘要，再锁所属酒店，在同事务中完成订单、占用、款项和成功日志。相同键、相同参数返回原结果；相同键换参数拒绝。数据库中的唯一键、外键、状态和金额约束是第二层约束；不能仅用页面按钮隐藏代替授权。

完整模拟证件只在住客登记表保存，日常读取只返回末四位，日志不拼接请求体或数据库异常中的SQL参数。图片先检查文件内容与像素总量，再解码重编码，使用服务器生成的UUID文件名；未批准图片仅所属前台和管理员可读，批准引用后才能公开访问。

这些措施与测试说明的是已实现、已核验的范围，不构成“绝无漏洞”的承诺。本程序面向本机课程实验，没有完成互联网生产部署、攻击流量防护、外部支付对账、备份运维和安全渗透验收。
