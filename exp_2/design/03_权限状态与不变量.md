# 权限、状态与不变量

本资料用于建模检查，不代表接口已经实现。

## 权限矩阵

| 操作 | 顾客 | 工作人员 | 管理员 | 自动任务 |
| --- | --- | --- | --- | --- |
| 已审核酒店房型与房源查询 | 可 | 可 | 可 | 不适用 |
| 顾客注册 | 仅注册顾客 | 不可自行注册员工 | 账号预配置 | 不可 |
| 在线付款、修改、取消 | 仅本人且状态允许 | 无代客权限推断 | 无代客权限推断 | 仅明确自动退款场景 |
| 订单查询 | 仅本人 | 仅本酒店 | 全部酒店 | 仅任务所需范围 |
| 接单、线下订房、入住退房、清洁 | 不可 | 仅本酒店且条件满足 | 无此默认权限 | 不可代替人工核验 |
| 资料、房量价格维护 | 不可 | 本酒店提交申请 | 审核，不默认为直接改价 | 不可 |
| 应急停售与影响处置 | 不可 | 本酒店，候选 A11 | 可查看，写权限待决 | 按有效应急事件执行已授权步骤 |
| 审核申请、设置费率 | 不可 | 不可自审 | 可 | 不可 |
| 全局统计、关键日志 | 不可 | 不擅自授予全局权限 | 可 | 写入任务日志 |

所有查询和变更都先做资源范围授权；未经授权的响应不能泄露订单存在性、金额或入住人。注册时忽略或拒绝客户端角色字段。UI 的身份切换只用于原型展示，不是系统真实认证方案。

线下确认入口采用 A07，同事务完成收款和占用。无论哪条路径都不得跳过全部入住夜校验。

禁止默认允许：待接单直接入住、已确认直接退房、已取消重新确认、已退房重新入住、其他顾客取消、本酒店员工操作他店订单、从旧页面覆盖新状态。未明确的“已入住取消”“提前退房退款”“应急终止已入住”不纳入普通取消接口。

## 分离的状态模型

- 订单：待接单 / 已确认 / 已入住 / 已退房 / 已取消 / 未入住结束。
- 模拟支付：未成功或成功；退款另建记录，不能用订单“已取消”推断退款完成。
- 房间：可安排 / 已入住 / 待清洁 / 故障停用。该候选集合表达当前接待条件，不代替未来逐夜房量。
- 资料申请：草稿 / 待审核 / 已通过 / 已驳回；生效资料保持独立版本。
- 修改请求：待用户确认 / 原单取消成功 / 新申请建立 / 新付款成功 / 新申请失败。只是一条协调记录，不改变原单已取消的事实。

## 必须始终成立的业务不变量

1. 任一房型任一入住夜：有效预订占用总量不超过允许接待容量；查询可售量同时受停售约束。
2. 多夜确认全部成功或全部不生效，不留下部分夜占用。
3. 待接单占用量为零；取消它不会释放不存在的占用。
4. 入住不重复扣库存；退房不重复增加库存；释放标记只能由有效占用变为已释放一次。
5. 订单成交价格是快照，后续改价不回写。
6. 退款必须关联本订单的成功付款与原模拟账户，累计退款不超过对应实付；重复请求不重复记账。
7. 同一请求键只产生一次业务效果；同键不同载荷拒绝；不同请求不能仅因同一顾客同一天而合并。
8. 终态不能被过期页面或后台任务恢复为有效订单。
9. 酒店故障解除前，退款释放占用不等于恢复可售。
10. 未清洁或故障房间不能办理下一次入住；入住登记涵盖全部入住人。
11. 预订、占用、款项和成功日志的一次业务提交有一致的结果；失败尝试另记，不伪装为成功业务。
12. 工作人员数据范围始终受所属酒店限制；管理员查全局并不意味着能代客取消。
13. 线上已确认未到店订单保留整个原住宿期，不能首晚未到就提前卖掉后续夜。
14. 原单修改取消已经成功后，新单业务无房不触发恢复原单。
15. 审核生效时重新检查最新占用，不能以申请提交时检查替代生效检查。

## 全局锁序候选

先鉴权，再取得所属酒店的库存协调锁，再按订单 ID 顺序读取并锁定目标及受影响订单，最后写入占用、款项和日志。取消、接单、审核、线下订房、到期及应急必须使用相同入口。修改的两个事务分别遵循锁序，不跨用户付款等待长期持锁。查询只返回快照，不承诺查询成功必定订房成功。
